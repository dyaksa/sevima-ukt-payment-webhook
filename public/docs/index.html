Introduction

Institution-isolated tuition invoices and signed mock gateway notifications.

Base URL: http://localhost:8000

All examples are synthetic. Invoice endpoints require a staff token; webhooks require an institution code and an HMAC over the exact request body. See README.md for setup, simulator scenarios and hand-signed requests.

Authenticating requests

To authenticate requests, include an Authorization header with the value "Bearer {STAFF_TOKEN}".

All authenticated endpoints are marked with a requires authentication badge in the documentation below.

Run vendor/bin/sail artisan token:issue finance@univ-a.test. Read routes require invoices:read; issuing an invoice requires invoices:write. Tokens belong to the staff user's institution. Webhooks use HMAC headers instead of a bearer token.

Invoices

List a student's invoices

requires authentication

Requires invoices:read. Returns only the caller's institution, newest semester first, with history ordered by occurred_at then id. An empty match returns data: []. The explicit institution filter is the second layer behind the global scope.

Example request:
curl --request GET \
    --get "http://localhost:8000/api/v1/invoices?student_number=20260001&semester=20261" \
    --header "Authorization: Bearer {STAFF_TOKEN}" \
    --header "Content-Type: application/json" \
    --header "Accept: application/json"

Issue an invoice

requires authentication

Requires invoices:write. Institution ownership comes from the staff token; a body institution_id is ignored. Duplicate invoice numbers in the same institution return 422. Identifiers must have no whitespace at their boundaries or control characters. The initial status is unpaid.

Example request:
curl --request POST \
    "http://localhost:8000/api/v1/invoices" \
    --header "Authorization: Bearer {STAFF_TOKEN}" \
    --header "Content-Type: application/json" \
    --header "Accept: application/json" \
    --data "{
    \"invoice_number\": \"INV-2026-0001\",
    \"student_number\": \"20260001\",
    \"semester\": \"20261\",
    \"amount\": 1500000,
    \"expires_at\": \"2027-01-01T00:00:00+00:00\"
}"

Webhooks

Receive a signed gateway notification

Sign the exact raw JSON bytes with HMAC-SHA256 using the institution's database secret as the literal text key (not hex-decoded). X-Signature is the lowercase hexadecimal digest. Verification precedes JSON validation. The example signature is a placeholder, not a valid signed request.

Canonical events (accepted aliases): payment.authorization (payment.pending), payment.capture (payment.success), payment.failure, payment_request.expiry (payment.expired), refund.succeeded (payment.refunded), and refund.failed. Event names are normalized before constructing the institution-scoped key. Captures sum captures[].capture_amount; refunds resolve through a prior gateway payment id, ignoring any reference_id. Only IDR is accepted. Every received notification is audited, including unauthorized and invalid requests. Every 2xx stops retries; reconciliation can recover unmatched events.

Example request:
curl --request POST \
    "http://localhost:8000/api/v1/webhooks/payments" \
    --header "X-Institution-Code: UNIV-A" \
    --header "X-Signature: {RAW_BODY_HMAC}" \
    --header "Content-Type: application/json" \
    --header "Accept: application/json" \
    --data "{
    \"event\": \"payment.capture\",
    \"business_id\": \"UNIV-A\",
    \"created\": \"2026-10-11T01:00:00Z\",
    \"data\": {
        \"payment_id\": \"py-example\",
        \"payment_request_id\": \"pr-example\",
        \"reference_id\": \"INV-2026-0001\",
        \"currency\": \"IDR\",
        \"updated\": \"2026-10-11T01:00:00Z\",
        \"captures\": [
            {
                \"capture_amount\": 1500000
            }
        ]
    }
}"

Example response (200, accepted):


200 {"outcome":"accepted"}

Body Parameters

Supported canonical event or alias. Example: payment.capture

Gateway account identifier; does not select the institution. Example: UNIV-A

Gateway envelope creation value; ordering uses data.updated instead. Example: 2026-10-11T01:00:00Z

Event resource.

Payment resource id; required for payment events and refunds, up to 64 characters. Example: py-example

payment_request_id   string  optional    

Required for expiry; up to 64 characters. Example: pr-example

id   string  optional    

Required refund resource id; up to 64 characters.

reference_id   string  optional    

Required invoice number for non-refund events; up to 64 characters. Example: INV-2026-0001

currency   string     

Must be IDR. Example: IDR

updated   string     

ISO 8601 with offset; after 2000-01-01 and at most one hour ahead of the server clock. Example: 2026-10-11T01:00:00Z

amount   integer  optional    

Required for refunds; whole rupiah from 1 to 1000000000000. Canonical digit strings also accepted.

captures   object[]  optional    

Required nonempty list for capture events.
capture_amount   integer     

Whole rupiah from 1 to 1000000000000; decimal and scientific notation are rejected. Example: 1500000
